# PR 생성

본문 형식의 기준은 `.github/PULL_REQUEST_TEMPLATE.md`입니다. 섹션과 주석 안내는 템플릿을 따르고, 이 스킬은 템플릿에 없는 절차만 정합니다. 기준 브랜치는 따로 지정이 없으면 `main`입니다.

## 1. 전제 점검

다음 중 하나라도 어긋나면 멈추고 알립니다.

- 현재 브랜치가 기준 브랜치가 아닙니다.
- 커밋하지 않은 변경이 없습니다(`git status --short`).
- 기준 브랜치보다 앞선 커밋이 있습니다(`git log origin/<base>..HEAD`).
- 이 브랜치로 열린 PR이 없습니다(`gh pr list --head <branch>`).

## 2. 제목

`commit` 스킬과 같은 형식입니다. 커밋이 하나면 그 메시지를 그대로, 여럿이면 전체를 대표하는 한 줄로 씁니다.

## 3. 본문

템플릿의 네 섹션(Intent, Changes, Decisions & Assumptions, Verification)을 한국어로 채웁니다. 섹션을 지우거나 추가하지 않고, HTML 주석은 지웁니다.

**원칙**
- 리뷰어가 diff를 열지 않고 본문만으로 이해하게 씁니다. 기능·동작·개념으로 쓰고 파일 경로, 클래스·함수 이름, 줄 수는 쓰지 않습니다.
- 렌더링되는 본문 기준(주석·URL 제외) **1000자 이내**, 내용이 있으면 800자 이상을 써서 의도·변경·결정을 충분히 설명합니다. 권장 배분은 템플릿 주석을 따릅니다. 1000자를 넘으면 문장을 줄이고, 그래도 넘으면 PR 분리를 제안합니다.
- 표시는 Verification에서 두 가지만 씁니다: `✅` 확인됨, `⚠️` 미확인·결정 필요·위험. 체크리스트는 쓰지 않습니다.

**섹션별**
- **Intent**: 문단으로 배경, 문제, 머지 후 도달하는 상태를 씁니다. 대화나 이슈에서 드러난 목적을 쓰고, diff만으로 알 수 없으면 추측하지 말고 묻습니다. 마지막 줄 `범위 밖:`에 일부러 하지 않은 것, 다른 PR에 의존하는 것, 미룬 후속 작업을 씁니다.
- **Changes**: 사용자나 시스템이 겪는 변화 하나당 `- **대상**: 전 → 후` 한 줄과, 그 아래 동작 설명 한두 문장. 이유는 쓰지 않습니다.
- **Decisions & Assumptions**: 대안이 있었던 결정마다 짧은 문단으로 무엇을 골랐고 왜인지, 버린 대안과 감수한 점을 씁니다. AI가 스스로 내린 판단은 빠짐없이 적습니다. 확인되지 않은 가정은 `가정:`으로 시작하는 문장으로 씁니다.
- **Verification**: 실제로 실행·확인한 것만 `✅`로, 증거는 CI 실행이나 스크린샷 링크로. 하지 않은 것을 통과했다고 쓰지 않습니다. 확인하지 못한 동작, 사람이 결정할 것, 회귀 위험은 `⚠️ 미확인:`, `⚠️ 결정 필요:`, `⚠️ 위험:`으로 씁니다.
- **남은 일 제안**: diff와 의도를 보고 시크릿·변수·라벨 설정, 배포 절차 변화, 상대 영역(`api-contract` 스킬 결과)에서 맞출 것, 첫 실행으로만 확인 가능한 가정을 찾아 Verification의 `⚠️` 줄 또는 `범위 밖`에 넣습니다. 올리기 전에 사용자에게 보여 확인받고, CI처럼 물을 수 없으면 그대로 올리고 AI 제안임을 알립니다.
- 관련 이슈가 있으면 `close #N`을 마지막 줄에 둡니다. Claude 작성 표시나 "Generated with" 줄은 넣지 않습니다.

**자체 점검**: 올리기 전에 본문만 보고 답할 수 있는지 확인하고, 답할 수 없으면 해당 섹션을 보완합니다.

1. 무엇이 문제였고 머지되면 무엇이 가능해지는가 (Intent)
2. 동작이 어떻게 바뀌는가 (Changes)
3. AI가 무엇을 왜 결정했고, 무엇을 확인 없이 가정했는가 (Decisions & Assumptions)
4. 무엇이 실제로 확인됐고 무엇이 남았는가 (Verification)
5. 800~1000자 사이인가 (내용이 적은 PR은 800자 미만 허용)

## 4. 푸시와 생성

1. PR 대상 저장소를 가리키는 원격으로 푸시합니다: `git push -u <remote> HEAD`. 원격이 여럿이면 `git remote -v`로 확인합니다.
2. 원격과 갈라졌으면 멈추고 물어봅니다. 자동 rebase나 force push는 하지 않습니다.
3. `gh pr create --base <base> --title "<제목>" --body-file <파일>`로 만들고(초안이면 `--draft`), PR 번호와 URL을 알립니다.
